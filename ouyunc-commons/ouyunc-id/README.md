# CosId 接入与故障行为

本模块保留 CosId 3.0.2、原 epoch 和 41/10/12 位布局。ID 在同一受控机器号分配范围内唯一，
不代表跨节点的业务提交顺序。不要用“全局严格递增”描述雪花 ID。

## 配置

机器号 namespace 按 JVM 属性 `-Douyunc.id.namespace=OUYUNC`、环境变量
`OUYUNC_ID_NAMESPACE`、默认值 `OUYUNC` 的顺序解析。显式空值拒绝启动。
该配置不读取 `ouyunc-server.yml`。namespace 不进入 ID 位段，不能通过不同 namespace
保证跨环境唯一；数据进入同一个消息库的节点必须使用协调一致的机器号分配域。
不要在滚动升级期间更改分配域、epoch 或位宽。

每个生成器实例使用主机诊断标签加启动 UUID，避免同主机多进程复用机器号。
不接受 `stable=true`；稳定身份需要额外的排他所有权协议。

## 生命周期与失效策略

- IM 服务监听前调用 `initializeManaged()`；初始化异常阻止本次启动。
- Redis 守护窗口为 300 秒，每 100 秒续约。本地有效期为 200 秒，从续约请求开始计算，
  使用单调计时，并预留 100 秒余量。正常发号只检查本地状态，不访问 Redis。
- 任意续约异常、期限耗尽、迟到的续约响应都会使机器号永久失效。即使 Redis 恢复，
  本进程也不会自动恢复发号；排障后应重启节点。此策略牺牲短暂故障下的可用性保护唯一性。
- `/ready` 和新登录准入读取 ID 健康状态；失效时不就绪。既有连接需要 ID 的操作会失败。
- 时钟回拨和当前毫秒序列耗尽直接抛异常，不在网络线程自旋或睡眠等待。
  上层应按原有失败/重试协议处理；禁止用随机 long、零值或重置 sequence 兜底。
- IM 统一排空结束后关闭生成器。关闭与发号互斥，关闭后不能懒加载重建。
  单独使用配置类时仍有 JVM 关闭钩子兜底；共享 Redis 连接工厂由缓存模块管理。
  关闭时若当前时间尚未超过最后发号时间，不主动归还机器号，避免回拨期间立即复用槽位。
- 格式转换不初始化 Redis。空字符串、负数拒绝；游标起点必须显式传零。

## 保证边界与上线验证

本地期限不提供跨进程 fencing，不能防御 Redis 分配记录被清空、回滚或错误迁移，
也不替代所有参与节点的时钟管理。Redis 分配状态应独立保护，不能作为普通缓存清理。
若要容忍分配存储丢失后新旧节点同时继续发号，应另行设计固定机器号分区或更强的分配协议。

上线前应在隔离环境验证：同 HOSTNAME 双进程获得不同机器号；Redis 断联后失效不恢复；
长暂停恢复后拒绝旧发号；并发关闭后不再返回新 ID；回拨与序列耗尽不等待；
格式转换在 Redis 不可达时仍可独立使用。本轮不添加或运行单元测试，编译结果不能替代这些验证。
